Why not train everything?

Full fine-tuning moves every weight, and keeps a copy per task

  • Gradients and optimiser state for every parameter: several times the memory of the weights
  • One full copy of the model for each task you tune
  • Every weight can move, so everything the base knew can be disturbed

The adapter's bet

The change a task needs is small and has structure. Freeze the base; learn only a low-rank correction to a few of its matrices.

AE-301 introduced low-rank adapters as an idea; today they are trained. The three costs on the left are memory, storage and forgetting. Adapters address the first two directly and the third only partly, as Day 4 will show.

Sources: Hu et al., LoRA: Low-Rank Adaptation of Large Language Models (2021).

Low-rank adaptation

W stays frozen; the adapter adds B·A beside it

Wd_out × d_in, frozen
+
Bd_out × r, starts at zero
·
Ar × d_in, starts random
×
alpha / ra fixed scale
  • Parameters added to one matrix: r × (d_in + d_out)
  • B starts at zero, so at step 0 the adapted model is the base
  • Which matrices get an adapter is a setting: today, the query and value projections of every attention layer

Draw it once on the board with numbers: a 1024 by 1024 matrix has about a million weights; a rank-8 adapter on it has 8 × 2048 = 16,384. The zero start of B is why Lab 3.1 can score "the base" through the freshly wrapped model.

Sources: Hu et al., LoRA (2021).

tuning.train, in essence

The whole training loop fits on a slide

params = [p for p in model.parameters() if p.requires_grad]      # the adapter only
opt = torch.optim.AdamW(params, lr=lr)
for step in range(steps):
    x, labels, mask = next_batch()               # rendered with the template; labels masked on the prompt
    for group in opt.param_groups:
        group["lr"] = lr * schedule(step)        # warm-up, then cosine decay
    loss = model(input_ids=x, attention_mask=mask, labels=labels).loss
    loss.backward()
    torch.nn.utils.clip_grad_norm_(params, 1.0)
    opt.step(); opt.zero_grad()
    if (step + 1) % 25 == 0:
        log(step, loss, loss_on(model, validation))

A plain loop on purpose: nothing today is hidden in a trainer class. Libraries such as TRL wrap exactly this and add checkpointing, logging and mixed precision; use them in a project, and know what they wrap. Point at the two lines that come from Day 2: the template and the label mask live in next_batch.

How many parameters train?

A base has 24 layers. You put a rank-8 adapter on the query and value projections of each layer; each is a 1,024 × 1,024 matrix. How many parameters train?

16,384
32,768
786,432
50,331,648
Why. Each adapted matrix adds r × (d_in + d_out) = 8 × 2,048 = 16,384. There are 2 × 24 = 48 of them: 48 × 16,384 = 786,432.

Answer: C. Follow-up: what happens to the count if the rank doubles? It doubles. If you add the other attention projections and the feed-forward matrices? It grows several times: targets are a larger lever on capacity than rank.

02
Do this before you rent anything

Whether a model fits is arithmetic: parameters times bits

Parameters16 bits4 bits
0.6 billion1.1 GB0.3 GB
1.7 billion3.2 GB0.8 GB
7 billion13.0 GB3.5 GB
27 billion50.3 GB13.4 GB

Weights only. 16 bits is two bytes a weight. 4 bits is half a byte, plus here one 16-bit scale for every block of 64 weights.

Computed with the function participants write in Lab 3.2: n × bits ÷ 8 ÷ 2^30. The 4-bit column uses a simplified accounting of the per-block constants; real libraries compress those further. Ask: which of these can be loaded on the accelerator you have access to, and which only in 4 bits?

Why "it fits" is not the end of it

The weights are the floor; training adds three things on top

Activations

Kept for every token of every example in the batch, at every layer, for the backward pass. Grows with batch size × sequence length.

Adapter gradients

Small: only A and B have them.

Optimiser state

Two more numbers for each trainable parameter with AdamW. Small for the same reason.

Out of memory with weights that fit? Lower the batch size or the maximum length first. Gradient accumulation keeps the effective batch.

This is why a base can be served on an accelerator on which it cannot be trained, and why the hub tier trims sequences to a maximum length. With an adapter, the base's own gradients are not stored, but activations still are: they are needed to reach the adapter in early layers.

Lab 3.2 · task 1

A 4-bit weight is one of 16 levels, times the scale of its block

scale   = block.abs().max()                          # one number kept per block of 64 weights
nearest = (block / scale - levels).abs().argmin()     # index of the closest of 16 levels: 4 bits
rounded = levels[nearest] * scale                     # what the model computes with
  • The 16 levels are not evenly spaced: they are denser near zero, where most weights of a trained network lie (the NF4 type)
  • Rounding is an error added to every weight. Whether it matters is an empirical question, per model and per task

On a GPU, bitsandbytes stores the 4-bit indices packed and converts them back in every forward pass. On a processor the course rounds the weights to the same 16 levels and leaves them in ordinary tensors: the effect on quality is real, the memory figure is computed rather than measured. The lab says so in its output.

Sources: Dettmers et al., QLoRA: Efficient Finetuning of Quantized LLMs (2023).

How much of the table is real?

One run per cell, one seed: a few requests in 120 is not a difference

  • The same setting and seed, run twice here: 85 and 89 of 120
  • A sweep read to the last digit chooses noise
  • The honest table has several seeds per cell, or an interval

The lab's rule

The highest validation score; among runs within 4 requests of the best, the one with the fewest trainable parameters. Chosen: rank 2 at 0.002, 86 of 120.

The rule is written before the table is read; that is what makes it a rule. "Within 4" is a judgement about noise on 120 requests, taken from what was measured: rank 8 at 0.002 with seed 310 scored 85 in the supplied run and 89 when the solution notebook of Lab 3.1 ran it again on the same laptop, because the order of a processor's arithmetic is not fixed between runs. A participant may defend a different margin. What is not defensible is choosing a cell because it is one request ahead.

Three questions before you distil

Distillation needs a better teacher, usable outputs and data that may be sent

Is the teacher better?

On this behaviour, measured on the same requests (Lab 1.1). A teacher that fails the same way has nothing to teach.

May its outputs train a model?

The licence of an open-weight teacher, or the terms of a hosted one. Read them as you read the student's licence on Day 1.

May the requests reach it?

Restricted requests may not go to a hosted teacher. Run the teacher on your own servers, or label synthetic and masked requests.

The third card is the chamber's case: the requirement that made it choose a small model also limits how it may build the tuning set. The generative AI guideline for government asks that information classified Restricted or higher is kept out of prompts to public tools.

Sources: SDAIA, Generative AI Guidelines for Government; NDMO, Data Classification Policy.
