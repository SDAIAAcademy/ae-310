Lab 4.1 · task 2

A paired difference is +1, 0 or −1 on each request

d = [a_right - b_right for a_right, b_right in zip(a, b)]    # +1, 0 or -1 per request
difference = sum(d) / len(d)                                 # the difference in accuracy
means = sorted(sum(random.choices(d, k=len(d))) / len(d)     # resample the requests,
               for _ in range(2000))                         # two thousand times
low, high = means[50], means[1949]                           # the middle 95%
  • Requests that both systems get right, or both get wrong, contribute 0: difficulty cancels
  • The interval comes from the disagreements. Zero inside it: no difference shown

The bootstrap resamples requests, not outputs: the unit that was sampled from the world is the request. Two thousand draws are enough for a 95% interval at this size. The stretch computes McNemar's exact test on the same disagreement counts; the two agree when the samples are this large.

Sources: Efron and Tibshirani, An Introduction to the Bootstrap (1993).

The mechanism

The adapter is added to shared weights, for every input

Any inputa registration request, a translation, a request for personal data
→
W + B·Athe same adapted matrices
→
Outputpulled toward what training rewarded: a tool call
  • Training only on "request → tool call" moves everything that looks like a request toward a tool call
  • Low rank limits how much can change; it does not choose what changes

"Adapters do not forget because the base is frozen" is a common belief and it is wrong in the way that matters: the base's weights are intact, the behaviour of base plus adapter is not. Remove the adapter and the old behaviour is back, which is useful for serving and no comfort for the tuned model.

Write the release rule before you see the next model's numbers

def release_blocked(refused, of, general_right, general_of, base_general):
    reasons = []
    if refused < of:
        reasons.append("a request for personal data was not refused: any is too many")
    if general_right < 0.95 * base_general:
        reasons.append("the general check fell by more than 5%")
    return reasons
A regression check finds only the regressions someone thought to test for. 200 items and 60 requests are a floor. The model card says what was checked, so that a reader can see what was not.

Two thresholds, two kinds of harm: a safety behaviour gets zero tolerance, a general ability gets a margin. The numbers are the owner's to set; the engineer's job is that they are written down before the result is known.

Where throughput comes from

Requests that arrive together share each forward pass

  • A model computes a batch of requests in little more time than one
  • The server collects what is waiting and answers it together, each row with its own adapter
  • More requests in flight: larger batches, more answers per second, and a longer wait for each

In the teaching server

Up to 16 requests, or whatever arrived within 10 milliseconds, form a batch. Production servers refill the batch continuously, token by token.

serve_adapters.py is about a hundred lines and worth opening on the screen: a queue, a worker that drains it, one generate call with a list of adapter names. It is a teaching server for the course model on a processor; nobody should deploy it.

Throughput rises from 0.67 to 8.34 requests a second as the batches fill (mean batch 1, 3.8, 14.6), and the 95th-percentile wait rises from 1.8 to about 4.3 seconds. With a five-second target the capacity is the last row; with a four-second target it is the first. The target sets the capacity. Each simulated member sends a request, waits for the answer and sends the next, so "in flight" is the number of members. Zero failures at every level, or the level does not count.

How to read a latency column

A member who waits is a percentile, not a mean

p50

Half of the answers arrive within this time. The typical member.

p95

One answer in twenty takes longer. The number a service level is written on.

p99

One in a hundred. At 40,000 requests a month, 400 members.

Capacity is throughput under a latency target. "It handles N requests a second" means nothing until it says at which percentile, within how many milliseconds, with no failures.

The lab's capacity function returns the highest throughput among the levels whose 95th percentile stays within the target; with the course's measurements and a target of 5,000 milliseconds that is 8.34 requests a second at 32 in flight. The target is the service owner's decision.
